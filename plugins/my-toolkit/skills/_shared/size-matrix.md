# Матриця розмірів — класифікація XS/S/M/L/XL + набір артефактів MVP чи Full

> **Лише довідка.** Це не скіл. Канонічний власник матриці — `sdlc:classify-size`; `write-prd` читає її,
> щоб класифікувати фічу на кроці 1, а інші скіли — щоб вирішити, скільки артефакту робити
> (MVP чи Full) і наскільки глибоко проводити сократівський прохід.

## Як класифікувати розмір

Чотири сигнали (`classify-size` ставить по одному `AskUserQuestion` на сигнал; `write-prd` — одне зведене):

| Сигнал | XS | S | M | L | XL |
|---|---|---|---|---|---|
| **Кількість PR** | 1 | 2–5 | 5–15 | 15+ | багато, поетапно |
| **Час до мержу основної частини** | ≤1 день | ~1 тиждень | 1–2 спринти | >1 місяця | свій роадмеп |
| **Новий модуль / нове API / міграція** | немає | ≤1 з трьох | 1–2 з трьох | 2–3 з трьох | нова підсистема |
| **Ламаючі зміни для споживачів** | немає | лише внутрішні | внутрішні або публічні | публічні | публічні + між командами |

- **XS** — 1 PR, ≤1 дня, без міграції, без нового API. (Опечатка, правка тексту, зміна конфігу.)
- **S** — 2–5 PR, ~1 тиждень, можливо невелика міграція.
- **M** — окремий епік, 1–2 спринти, новий модуль / API / міграція.
- **L** — кілька модулів, кілька команд, можливі ламаючі зміни.
- **XL** — нова підсистема, потребує окремого роадмепу.

У межових випадках назви домінантний сигнал: «це M, бо додається нове API + 1–2 спринти, хоча кількість PR на межі S/M».

> **Правило одного речення.** Якщо вагаєшся між MVP і Full — починай з MVP. Дописати порожні секції артефакту пізніше дешевше, ніж викидати наперед написані.

## Набір артефактів MVP чи Full

| Артефакт (скіл) | MVP (XS/S) | Full (M+) |
|---|---|---|
| бриф ідеї — `my-toolkit:interview` | так (easy) | так |
| PRD — `my-toolkit:write-prd` | так | так |
| уточнення PRD — `my-toolkit:clarify-prd` | легке (пропустити, якщо немає неоднозначностей) | так |
| глосарій CONTEXT.md — `my-toolkit:fix-term` | так | так |
| SAD (Arc42, 12 §) + C4 L1/L2 — `sdlc:architecture-design` | 12 секцій пройдено, більше `<!-- N/A -->` | усі 12 заповнено |

## Кількість поверхонь — друга вісь масштабу

Розмір (XS–XL) — регулятор *глибини*; кількість **цільових поверхонь** (target surfaces), які заявляє фіча (у `sdlc:architecture-design`, записуються у frontmatter `sad.md` як `target_surfaces`; таксономія — у `_shared/surfaces.md` плагіна `sdlc`), — друга вісь, *ширина* набору артефактів. Кожна поверхня додає свою роботу: UI-поверхня (`web-frontend` / `mobile-app` / `desktop-app`) додає шар задач `ui`, UI-потоки в §6 і рівні тестів компонентів / візуальної регресії / e2e через UI; поверхні `cli` / `worker` / `library-sdk` додають свою форму контракту + потоки. Тож фіча з кількома поверхнями (`[backend-service, web-frontend]`) справді **більша** за фічу з однією поверхнею того самого класу XS/S/M — окремої колонки тут немає, але чекай більше задач, потоків і рядків тестів на кожну додаткову поверхню.

## Як розмір впливає на SAD

Навіть для XS/S `architecture-design` проходить усі 12 секцій Arc42 — послідовність важливіша за театр повноти. Секції, які справді не стосуються фічі, отримують `<!-- N/A: <причина в один рядок> -->`. Типові N/A для XS/S:

- §7 Розгортання — `<!-- N/A: використовує наявну одиницю розгортання, інфраструктура не змінюється -->`
- §6 Runtime — згортається до **найменшої кількості потоків, що все ж покривають кожен AC з §5** (часто один потік з гілками помилок усередині як `alt`, а не окремі потоки збоїв). Згортаються деталі, але не покриття AC — `complete-sequence-diagrams` усе одно прив'язує кожен AC до потоку, гілки або явного N/A навіть на XS/S.
- §11 Ризики — один рядок прийнятого техборгу, без середніх / високих ризиків.

Той самий скіл, той самий шаблон, менший обсяг змісту.

## Обгортки / перевірки

Скіл, що читає `.size`, пропускає важкі підартефакти для XS/S (окремий тест-план, вид розгортання, повний набір ADR). `write-prd` **встановлює `.size` на початку основного шляху** (класифікує і записує, якщо файлу немає), тож пізніші етапи зазвичай читають справжній розмір. Етап, який *усе одно* не знаходить його (напр. `architecture-design`, запущений окремо, до `write-prd`), бере **M** за замовчуванням (безпечне надвиробництво) **і каже про це в блоці передачі** — ніколи не мовчки.
