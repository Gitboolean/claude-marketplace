# Склад агентів — політика model / effort + спільний контракт агента

> **Лише довідка.** Це не скіл. Скіли читають цей файл для матриці model/effort, порядку
> перевизначень і контракту, якого дотримується кожен запущений агент. Канонічні визначення агентів
> живуть у `agents/*.md` цього плагіна; цей файл — політика, що їх поєднує.

## Склад (model + effort за роллю)

Модель обирається за **типом роботи**, а не за смаком: судження отримує найсильнішу модель, збір і цитування — збалансовану. Effort — потрібна ролі глибина міркувань.

| Агент | Тип роботи | `model` | `effort` | Інструменти | Хто запускає |
|---|---|---|---|---|---|
| `researcher` | дослідження конкурентів / суміжних рішень (ідеація) | `sonnet` | `medium` | Read, Grep, Glob, WebSearch, WebFetch | `interview`, фаза 4 |
| `strategist` | три стратегічні підходи (судження) | `opus` | `high` | Read, Grep, Glob | `interview`, фаза 5 |
| `analyst` | оцінка підходів з кількох ролей (судження) | `opus` | `high` | Read, Grep, Glob | `interview`, фаза 6 |
| `devils-advocate` | пошук сценаріїв провалу / неоднозначностей (судження) | `opus` | `high` | Read, Grep, Glob | `interview`, фаза 8; `clarify-prd`, крок 3 |
| `critic` | критика узгодженості (судження) | `opus` | `high` | Read, Grep, Glob | `write-prd`, крок 8 |

Обґрунтування: якість суджень (критика, неоднозначності, стратегія, синтез поглядів) — саме там, де сильніша модель окупається; `researcher` збирає й цитує, тому йому вистачає збалансованої моделі з веб-інструментами. (Сприймай «модель за роллю» як розумний принцип: популярне твердження «сильніший оркестратор + дешевші виконавці виграють на X%» з літератури про мультиагентні системи перевірки не пройшло, тож ми спираємося на відповідність ролі, а не на магічне співвідношення.)

Агенти етапів реалізації (`explorer`, `test-author`, `implementer`, `refactor`, `reviewer`, `doc-flow`) поки лишаються в плагіні `sdlc` і запускаються як `sdlc:<name>`.

## Запуск (`subagent_type`)

Агенти мають **простір імен плагіна**. Запускай кожного з `subagent_type: "my-toolkit:<name>"` — це id, який Claude Code реєструє і показує в переліку доступних агентів, — **не** голою назвою:

`my-toolkit:researcher` · `my-toolkit:strategist` · `my-toolkit:analyst` · `my-toolkit:devils-advocate` · `my-toolkit:critic`

Тож коли скіл каже «запусти агента `critic`», виклик — `subagent_type: "my-toolkit:critic"`. Якщо агента з простором імен під час виконання немає — запасний варіант `general-purpose`, який називає скіл, з тим самим промптом.

## Порядок перевизначень (вищий перемагає)

```
змінна середовища  >  конкретний виклик (Agent)  >  frontmatter  >  сесія
```

- **`model`** через змінну: `CLAUDE_CODE_SUBAGENT_MODEL`. Значення: `haiku|sonnet|opus|inherit|<повний-id-моделі>`.
- **`effort`** через змінну: `CLAUDE_CODE_EFFORT_LEVEL`. Значення: `low|medium|high|xhigh|max|<число>`.

> **Застереження (перевір на своїй збірці).** На деяких збірках Claude Code поле `effort:` у
> *frontmatter* не мало помітного ефекту під час виконання (GitHub claude-code#43083). Поле
> задокументоване, і ми його ставимо, але надійним важелем вважай **змінну середовища**
> (`CLAUDE_CODE_EFFORT_LEVEL`). Якщо запуск здається недодуманим — постав змінну.

## Спільний контракт агента (кожен запущений агент)

1. **За замовчуванням — чистий ізольований контекст.** Запущений агент **не** бачить батьківської розмови, результатів інструментів, системного промпту, викликаних скілів чи вже прочитаних файлів — **єдиний канал — рядок промпту Agent**. Тож скіл, що запускає агента, мусить явно передати шляхи, чернетку / diff і рішення; попередні артефакти агент перечитує сам. Повертається лише фінальне повідомлення агента. Ця ізоляція *і є* «форком» для незалежного рев'ю / критики — свіжий погляд і є сенсом.
   - **Режим форку** (`CLAUDE_CODE_FORK_SUBAGENT`, експериментальний) успадковує всю розмову і спільний кеш промптів. Використовуй його **лише** для побічної задачі, якій справді потрібен поточний контекст, — ніколи для `critic` / `devils-advocate`, чия цінність — незалежність.
2. **Перевір, перш ніж заявляти «готово».** Перш ніж сказати «готово / виправлено / проходить»: ВИЗНАЧ команду, що це доводить → ЗАПУСТИ її → ПРОЧИТАЙ вивід → лише тоді заявляй, з доказом. Слова «мало б / мабуть / схоже» — червоний прапорець, що перевірки не було.
3. **Посилайся або викидай.** Агенти суджень лише для читання (critic / devils-advocate) видають лише знахідки з посиланнями (`файл:рядок` + пункт артефакту / AC). Знахідку без посилання викидають, а не передають.
